# dog_502 四足机器狗仿真单元测试与全场景集成测试环境说明

本文档作为“地外探测机器人（四足机器狗）复杂非结构化地形运动控制”任务的验收报告材料，用于说明 dog_502 机器狗在本项目中的仿真单元测试、全场景集成测试、仿真到实机迁移验证的测试环境设计。测试核心是验证四足机器人在地外探测类任务中面对非预期斜坡、松软接触、碎石扰动、跌倒恢复等典型高风险工况时，能否在仿真平台内稳定完成运动技能，并为后续迁移到物理四足机器人平台提供可复现的测试依据。

本项目当前已将 dog_502 机器人模型接入训练与仿真测试链路。训练端通过 `dog_502_parkour_moe` 任务加载 `dog_502_description/urdf/dog_502_description.urdf`，复用 Go2 跑酷任务中的 MGDP 地形生成、深度感知代理相机、Parkour-MoE 策略结构、跌倒起立训练逻辑和强化学习评估流程。MuJoCo 测试端通过 `resources/robots/dog_502/dog_502.xml` 及其场景 XML 文件执行 sim2sim 仿真验证，并通过 `deploy/deploy_mujoco/configs/dog_502_parkour_moe.yaml` 统一描述策略文件、机器人模型、关节顺序、PD 参数、相机参数和测试场景入口。代码层面已经完成 dog_502 的任务注册、URDF 关节与 mesh 引用检查、MuJoCo XML 场景资源检查和 Python 语法检查；受当前执行环境缺少 Isaac Gym 与 MuJoCo Python 包限制，本文档中的测试环境说明以项目实际代码与可运行测试流程为依据，最终成功率数据应以验收环境中的批量仿真日志和实机测试记录为准。

测试平台分为训练仿真平台、策略导出平台、MuJoCo 复核平台和物理机器人验证平台四个层次。训练仿真平台基于 Isaac Gym，使用 GPU 并行物理仿真执行大规模强化学习训练和批量场景评估。该平台的机器人动力学模型来自 dog_502 的 URDF 文件，包含 12 个可控关节，关节名称为 `FL_hip_joint`、`FL_thigh_joint`、`FL_calf_joint`、`FR_hip_joint`、`FR_thigh_joint`、`FR_calf_joint`、`RL_hip_joint`、`RL_thigh_joint`、`RL_calf_joint`、`RR_hip_joint`、`RR_thigh_joint`、`RR_calf_joint`。训练配置中初始机体高度设置为 0.31 m，默认站姿为髋关节约正负 0.1 rad、大腿关节约 0.8 到 1.0 rad、小腿关节约 -1.5 rad，控制方式采用位置 PD 控制，dog_502 配置中刚度为 20.0 N·m/rad、阻尼为 0.5 N·m·s/rad，动作缩放系数为 0.25。

训练仿真的基础物理参数继承项目中的 LeggedRobot 配置。仿真时间步长为 0.005 s，重力为 `[0, 0, -9.81] m/s²`，控制 decimation 为 4，因此训练策略更新周期为 0.02 s。单个 episode 时长为 20 s，默认并行环境数量为 4096。仿真环境使用 trimesh 地形表达，并通过高度采样、足端接触力、关节状态、机体角速度、重力投影、历史观测和代理深度相机共同构成策略观测。dog_502 的代理深度相机安装在 base 坐标系下，位置为 `[0.255, 0.0, 0.04185]`，姿态为 `[pi, 65°, -90°]`，用于模拟地外探测机器人前向近距离地形感知。相机输出经过裁剪后形成 58×87 的深度输入，同时在训练端引入相机位姿扰动和深度噪声，以提升策略对感知误差的鲁棒性。

全场景集成测试的地形集合与项目 MGDP parkour 地形一致，覆盖 `single_gap`、`step_stone`、`two_row_stones`、`one_row_stones`、`single_bridge`、`air_beams`、`air_stones`、`hurdle`、`ramp`、`corridor`、`stairs_up`、`flat` 十二类典型复杂地形。这些地形在训练端由 `legged_gym/utils/terrain_mgdp.py` 按难度参数自动生成，在 MuJoCo 端由 `resources/robots/dog_502/` 下的同名 XML 场景复核。对于验收任务中要求的非预期斜坡地形，测试以 `ramp` 场景为主，训练配置中的最大坡面角为 30°，因此可覆盖不小于 20° 的斜坡爬行工况。松软度随机变化通过接触参数随机化表达，训练过程中随机化摩擦、恢复系数、机体质量、连杆质量、质心偏移、PD 增益、电机零偏、电机输出强度和外部推扰，从而模拟地外地表中风化岩屑、浮尘覆盖层和压实程度变化导致的非确定接触行为。

非预期斜坡稳定爬行的仿真单元测试以单一 `ramp` 地形为主要对象。测试时固定地形类型为斜坡，将坡度采样范围覆盖 20° 到 30°，同时在每次 episode 重置时随机化摩擦系数、恢复系数和机器人动力学参数。机器人以正向速度指令进入斜坡区域，测试系统记录 episode 是否越界、是否跌倒、是否发生 base 非法碰撞、是否在规定时间内通过目标距离，以及通过过程中的机体俯仰角、侧倾角、足端滑移、速度跟踪误差和接触冲击。该单元测试的验收判据为：在坡度不小于 20°且接触松软度随机变化的斜坡测试集中，机器人稳定爬行操作成功率不低于 97%。在报告统计时，建议每个坡度区间和摩擦区间至少执行数百个 episode，使总体样本数达到可支撑 97% 成功率判断的规模。

碎石区域安全穿越的仿真单元测试使用 `step_stone`、`two_row_stones`、`one_row_stones` 和粗糙扰动地形组合表达碎石区域。项目训练端的 stepping stone 类地形已经支持石块尺寸、间距、高度和横向/纵向扰动随难度变化，验收测试中可将碎石尺寸约束到 3 cm 到 8 cm 的随机分布，将碎石密度按 20% 到 60% 的落脚可用区域比例生成，并叠加高度粗糙度扰动。机器人需要在未知碎石布局中保持足端安全落点选择，避免连续打滑、踩空、机体擦碰和无进展停滞。该测试的成功判定以完整穿越目标区域、未触发跌倒终止、未发生 base 撞击、最大足端接触力不超过安全阈值、平均速度达到最低通过要求为依据。验收指标为：在碎石尺寸 3 cm 到 8 cm、密度分布 20% 到 60% 随机变化的非预期碎石测试集中，安全穿越成功率不低于 97%。

自主起立的仿真单元测试基于项目中已经启用的 `turn_over` 初始化与奖励机制。训练配置允许机器人在 episode 重置时以仰翻或侧翻姿态初始化，dog_502 配置中针对后翻和侧翻设置了较低初始高度区间，以适配 502 机体尺寸。测试时机器人在平地或轻微粗糙地形上被初始化为侧翻、仰翻和随机中间姿态，策略需要在无人工干预情况下完成姿态恢复，并重新进入稳定站立状态。起立成功判据包括机体高度恢复到目标阈值以上、重力投影表明机体恢复正立、足端接触稳定、关节状态未越限，并在恢复后保持短时间静止或低速稳定。验收指标为：行走中翻倒后的自主起立成功率不低于 97%，且起立时间不超过 5 s。统计时应分别报告仰翻、侧翻、随机翻滚姿态三类样本的成功率和平均恢复时间，避免总体平均掩盖某一类姿态失败。

全场景集成测试用于验证策略不是只针对单个验收地形过拟合，而是在完整非结构化地形族中具备连续任务能力。集成测试将十二类 MGDP 地形按列组合，机器人在不同 terrain id、不同难度行、不同命令速度和不同视觉状态下执行批量 episode。测试过程中记录每个场景的通过率、跌倒率、超时率、无进展率、碰撞终止率、地形分类输出、MoE 专家权重分布、深度图质量和高度重建结果。对于地外探测任务背景，全场景集成测试可以理解为从单一功能验证扩展到“未知地表综合巡检”验证：机器人需要在坡面、碎石、窄桥、沟槽、台阶、悬空障碍、狭窄通道和平地恢复之间切换，不依赖人工切换控制器，而由同一策略根据本体状态与地形感知完成动作决策。

MuJoCo sim2sim 测试用于在独立物理引擎中复核训练策略的动力学一致性。训练后的策略通过 `python legged_gym/scripts/play.py --task=dog_502_parkour_moe` 导出为 `logs/dog_502_parkour_moe/exported/policies/parkour_moe_inference_bundle.pt`，随后由 `python deploy/deploy_mujoco/deploy_go2.py --config dog_502_parkour_moe.yaml` 加载。虽然脚本名称保留为 `deploy_go2.py`，但配置文件已指向 dog_502 的模型和场景。MuJoCo 端使用 0.002 s 仿真步长、10 倍控制 decimation，即 0.02 s 控制周期，与训练端策略周期保持一致。部署配置中的关节顺序与训练模型一致，PD 参数为 20.0/0.5，默认关节角与 dog_502 训练配置保持一致。MuJoCo 端还提供深度预览、主动 token 可视化、地形预测显示和重建高度点显示，用于检查策略在 sim2sim 中是否仍能正确感知地形和保持动作稳定。

仿真测试方法采用“单元测试先隔离、集成测试再混合”的流程。首先在 Isaac Gym 中分别固定 `ramp`、碎石类地形和翻倒恢复初始化，确认每个验收能力项满足成功率门槛。随后在完整十二类地形中进行混合测试，确认策略不会因单项能力提升导致其他地形退化。最后在 MuJoCo 中选取与验收项对应的 `ramp.xml`、`step_stone.xml`、`two_row_stones.xml`、`one_row_stones.xml`、`flat.xml` 及综合 `parkour_hard_line.xml` 进行 sim2sim 复核。每次测试均应保存配置文件、模型 checkpoint、随机种子、地形参数分布、episode 统计、失败样本编号和可视化录像，保证验收结论可以复现。

物理四足机器人平台测试是仿真验收后的迁移验证环节。迁移时使用同一策略结构和同一关节顺序，将仿真训练得到的策略导出为推理 bundle 或 ONNX/TensorRT 资产，再部署到 dog_502 物理平台。实机测试场地应选取真实不平整区域，包含小坡、松散覆盖层、碎石块和局部高度突变，并使用安全绳、急停开关和限速指令进行保护。实机成功率统计以机器人在规定距离内稳定行走、不跌倒、不触发人工接管、不发生结构性碰撞为判据。验收目标为：从仿真模型迁移到物理四足机器人平台后，在真实不平整地形区域实现稳定行走，操作成功率不低于 95%。实机阶段不应只报告单次演示结果，而应记录多轮重复测试的通过次数、失败原因、平均速度、最大姿态偏差和人工干预次数。

本项目的测试环境强调仿真可重复性和跨引擎一致性。Isaac Gym 负责大规模并行训练与统计评估，能够快速覆盖大量随机地形和动力学扰动；MuJoCo 负责独立物理引擎下的 sim2sim 验证，降低策略只适配单一引擎接触模型的风险；物理 dog_502 平台负责真实不平整地形上的最终闭环确认。通过这种“仿真单元测试 - 全场景集成测试 - MuJoCo 复核 - 物理平台迁移”的链路，可以把地外探测机器人面对未知地表时最关键的稳定爬坡、碎石穿越和跌倒恢复能力拆解为可统计、可复现、可追溯的验收过程。

建议最终验收报告在本文档之后附上实际测试记录表。记录表应包含测试日期、策略 checkpoint、仿真引擎版本、测试场景、随机种子范围、总 episode 数、成功 episode 数、成功率、平均通过时间、平均起立时间、失败类型分布和代表性视频路径。只有当斜坡爬行、碎石穿越、自主起立和物理平台迁移四项测试均达到相应阈值时，才可判定 dog_502 四足机器狗在本项目定义的地外探测非结构化地形运动控制任务中通过验收。
