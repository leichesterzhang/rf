# 机器狗可通行性自主目标跟踪导航技术方案

> 面向当前 `go2_parkour_moe` 机器狗跑酷控制项目的上层自主导航扩展方案。  
> 目标是在无人为遥控速度指令时，机器狗能够结合摄像头/传感器目标追踪结果与已建点云地图，主动规划一条“既能跟踪目标，又知道何时跨越障碍、何时绕行”的高效导航路径。

## 1. 背景与问题定义

当前项目已经具备较强的底层运动通行能力：

- 可以在楼梯、沟渠、独木桥、斜坡、hurdle、石块、窄通道、悬空梁/平台等多种 parkour 地形上训练行走。
- 现有 `Parkour MoE` 策略通过本体状态、历史状态和深度输入生成 `mcp_code`，再由 actor 输出 12 维关节残差动作。
- 实机部署链路中，控制器目前主要依赖人为遥控输出 `cmd = [lin_vel_x, lin_vel_y, ang_vel_yaw]`，策略负责执行这个速度/转向意图。

当前缺口在于：

- 底层策略会“走”，但不会自己决定“去哪里走”。
- 普通导航只会把障碍物视为不可通行区域并绕开，无法利用机器狗已有的跨沟、上楼梯、跨障碍、过桥能力。
- 当目标在复杂地形中移动时，最短、最快或最稳定的路线不一定是完全避障路线，有时应主动跨越低矮障碍、过窄桥、上台阶或穿越沟渠。

因此，本方案新增一个上层自主导航与可通行性决策系统，使机器狗从“被人给速度指令”升级为“自己看地图、看目标、判断地形可通行性，并给底层控制器下发速度/局部目标指令”。

## 2. 建设目标

### 2.1 总目标

训练并部署一个可通行性自主目标跟踪导航系统，使机器狗能够：

1. 根据摄像头、深度、激光雷达或其他传感器追踪目标。
2. 根据实时点云/高度地图建立局部与全局地图。
3. 分析地图中的障碍物几何信息，包括高度、宽度、沟渠宽度、坡度、台阶高度、桥面宽度、地形连续性等。
4. 判断不同区域是：
   - 可直接通行；
   - 可跨越/攀爬/上坡/上台阶通行；
   - 风险较高但可尝试；
   - 大概率无法通过，需要绕行；
   - 不确定，需要降低速度或重新感知。
5. 在追踪目标时规划高效路线，而不是简单避障。
6. 将规划结果转化为当前项目底层控制器可执行的速度指令或局部路点指令。

### 2.2 不直接替换的部分

本方案不建议直接替换当前 `Parkour MoE` 底层运动控制策略。原因是：

- 当前底层策略已经学习到大量地形通过能力，应作为运动执行器复用。
- 上层导航的时间尺度更慢，关注地图、路径和目标；底层控制的时间尺度更快，关注身体稳定和关节动作。
- 分层结构更容易调试、部署和做安全兜底。

因此整体目标是：

```text
+----------------------------------+
|  新增：自主导航与可通行性决策网络   |
|  输入：目标、点云/高度图、机器人状态 |
|  输出：局部路点或速度指令           |
+-----------------+----------------+
                  |
                  v
+----------------------------------+
|  复用：现有 Parkour MoE 控制策略    |
|  输入：cmd、本体观测、深度/视觉      |
|  输出：12 维关节动作                |
+----------------------------------+
```

## 3. 总体技术路线

推荐采用“学习式可通行性评估 + 经典/学习式路径规划 + 现有底层控制器执行”的混合架构。

不建议一开始采用完全端到端方案：

```text
点云 + 目标图像 -> 网络 -> 关节动作
```

因为这种方案训练难度大、样本效率低、实机安全风险高，而且会浪费当前已经训练好的 parkour 控制能力。

推荐架构为：

```text
传感器数据
  ├─ 目标检测/跟踪
  ├─ SLAM / 位姿估计
  └─ 点云/深度/高度地图
        |
        v
局部地形表征构建
  - 高度图
  - 坡度图
  - 障碍高度图
  - 沟渠宽度图
  - 台阶/坡面/桥/窄通道特征
        |
        v
可通行性网络 Traversability Network
  - 预测每个栅格/局部片段的通过概率
  - 预测通过代价
  - 预测推荐通过模式
  - 预测不确定性/风险
        |
        v
目标跟踪导航策略 Navigation Policy / Planner
  - 结合目标位置、地图代价、机器人状态
  - 生成全局/局部路径
  - 输出局部路点或速度指令
        |
        v
速度指令转换器 Command Generator
  - cmd = [vx, vy, yaw_rate]
        |
        v
现有 Parkour MoE 底层控制器
```

## 4. 系统模块设计

### 4.1 感知与建图模块

输入来源：

- RGB 摄像头：用于目标检测、目标 ReID、目标跟踪。
- 深度相机或双目：用于近距离障碍几何。
- 激光雷达/点云：用于中远距离地图和障碍物结构。
- IMU、关节状态、里程计或视觉惯性里程计：用于机器人自身位姿估计。

输出地图建议采用多层二维栅格地图，而不是直接把原始点云喂给规划器：

```text
local_map: [C, H, W]

C 可包含：
- height_mean：地面/障碍平均高度
- height_max：局部最大高度
- height_min：局部最低高度，用于沟渠检测
- height_var：高度变化/粗糙度
- slope：坡度
- step_edge：台阶/断崖边缘强度
- gap_width_hint：沟渠/空洞宽度线索
- obstacle_width_hint：障碍物宽度线索
- traversed_history：近期是否走过
- target_likelihood：目标可能位置
- unknown_mask：未知区域
- dynamic_mask：动态障碍区域
```

地图坐标建议：

- 局部地图以机器人为中心，例如 `8 m x 8 m` 或 `12 m x 12 m`。
- 分辨率建议 `0.05 m ~ 0.10 m`，与当前高度场 `horizontal_scale = 0.05 m` 尽量对齐。
- 全局地图用于长距离追踪，局部地图用于策略实时决策。

### 4.2 目标跟踪模块

目标跟踪模块输出不是简单的图像框，而是导航可用的目标状态：

```text
target_state:
- target_position_map: 目标在地图坐标系下的位置
- target_velocity_map: 目标速度估计
- target_visible: 当前是否可见
- target_confidence: 目标跟踪置信度
- target_last_seen_position: 丢失前最后位置
- target_predicted_position: 短时预测位置
```

目标可见时，导航策略追踪当前目标位置；目标短时丢失时，策略追踪预测位置或最后可见位置；目标长期丢失时，切换到搜索模式。

### 4.3 可通行性网络

这是本方案的核心模块。

普通导航中的 costmap 通常只区分“障碍/非障碍”，本项目需要的是“动作条件化可通行性”：

```text
同一个障碍，对轮式机器人是不可通行；
对普通四足机器人可能要绕行；
对当前 parkour 策略，可能可以跨越、上台阶、过桥或跳沟。
```

可通行性网络输入：

```text
- local_map: 多层局部高度/点云特征图
- robot_state: 当前速度、姿态、朝向、估计稳定性
- policy_context: 当前 Parkour MoE 的地形预测、vision flag、mcp_code 可选摘要
- target_context: 目标相对位置、目标速度、目标可见性
- command_history: 最近若干帧上层指令与执行结果
```

可通行性网络输出：

```text
traversability_map:
- pass_prob: 每个栅格/候选通道的通过成功概率
- traversal_cost: 通过代价，越低越优
- risk: 跌倒、卡住、偏航、失足风险
- mode_logits: 推荐通过模式
    - flat_walk
    - stair
    - ramp
    - gap_cross
    - hurdle_cross
    - bridge
    - narrow_corridor
    - avoid
- speed_limit: 推荐最大通过速度
- uncertainty: 感知或策略不确定性
```

关键点：网络不是简单预测“有没有障碍物”，而是预测“以当前机器狗能力和状态，这片区域是否值得通过，以及应该用什么方式通过”。

### 4.4 导航规划模块

导航规划可以有两种实现方式。

#### 方案 A：学习式可通行性 + 经典规划器

这是推荐的第一阶段方案。

流程：

```text
local/global map
    -> 可通行性网络生成 cost/risk/mode map
    -> A* / D* Lite / Hybrid A* / MPC 规划路径
    -> 路径跟踪器生成 cmd
    -> Parkour MoE 执行
```

优点：

- 可解释性强。
- 容易调试每个模块。
- 实机更安全。
- 可以直接利用传统路径规划的稳定性。

规划代价函数示例：

```text
cost = 路径长度代价
     + 时间代价
     + 风险代价
     + 不确定性代价
     + 目标丢失代价
     + 过度绕行代价
     + 模式切换代价
```

其中“可跨越障碍”通过较低的 learned traversal cost 体现；“不可通过障碍”通过极高 cost 或 hard block 体现。

#### 方案 B：端到端局部导航策略

第二阶段可以训练一个局部导航策略，直接输出局部路点或速度指令：

```text
local_map + target_state + robot_state
    -> Navigation Policy
    -> local_goal / cmd
```

输出建议优先选择局部路点：

```text
local_goal = [x, y, yaw]
```

再由 command generator 转成：

```text
cmd = [lin_vel_x, lin_vel_y, ang_vel_yaw]
```

原因是局部路点比直接速度更稳定，也更容易与全局规划器融合。

### 4.5 指令生成模块

现有实机部署中，`obs[6:9]` 接收人为遥控的 `cmd`。新增自主导航后，指令来源改成：

```text
if remote_control_enabled:
    cmd = remote_controller_cmd
else:
    cmd = autonomous_navigation_cmd
```

指令生成器需要把路径/局部路点转换为底层策略熟悉的速度范围：

```text
lin_vel_x:      0.0 ~ 1.5 m/s
lin_vel_y:      根据底层训练能力逐步开放
ang_vel_yaw:   -1.0 ~ 1.0 rad/s，必要时可限幅
```

注意：当前 parkour 主任务大量地形仍偏前向通关，`lin_vel_y` 训练较少。因此初期建议让上层规划尽量生成“转向后前进”的路径，而不是要求底层长期横移。

## 5. 训练环境设计

### 5.1 大训练地图生成

需要从当前单块 parkour 地形扩展为“大地图组合地形”。

当前项目的地形主要是：

- 单块 `10 m x 4 m` 地形；
- 纵向通关；
- 每个 episode 主要沿 `+x` 前进。

自主导航训练需要改成：

- 更大的二维地图，例如 `20 m x 20 m`、`40 m x 40 m` 或更大；
- 随机组合楼梯、沟渠、桥、坡、hurdle、石块、墙体、窄通道、平地；
- 随机设置起点、目标点；
- 目标可以静止，也可以移动；
- 允许存在多条路线：绕行路线、安全路线、短但有障碍路线、高风险捷径。

地图生成方式：

```text
大地图 = 多个 terrain tile + 随机障碍物 + 连接区域

tile 类型：
- flat
- stairs_up / stairs_down
- ramp
- single_gap
- hurdle
- single_bridge
- one_row_stones / two_row_stones
- corridor
- air_beams / air_stones
- wall / dead-end
- unknown / occluded area
```

每个 tile 需要记录语义和几何标签：

```text
tile_label:
- terrain_id
- difficulty
- obstacle_height
- obstacle_width
- gap_width
- slope_angle
- bridge_width
- step_height
- expected_success_rate
- recommended_mode
```

### 5.2 地图难度课程

建议使用三层课程。

第一层：单障碍导航。

- 起点和目标之间只有一种地形挑战。
- 网络学习基本判断：矮障碍跨越，高障碍绕行；窄沟可跨，宽沟绕行；缓坡可走，陡坡绕行。

第二层：多障碍组合。

- 同一张地图中同时出现沟渠、楼梯、桥、坡、hurdle。
- 网络学习路线权衡：短路径有障碍，长路径更平稳。

第三层：目标动态追踪。

- 目标会移动、短时遮挡、改变方向。
- 网络学习实时重规划、追踪预测和目标丢失恢复。

课程参数建议：

```text
obstacle_height: 0.05 m -> 0.70 m
gap_width:       0.10 m -> 1.00 m
step_height:     0.05 m -> 0.25 m
slope_angle:     0 deg  -> 30 deg
bridge_width:    0.60 m -> 0.25 m
map_size:        10 m   -> 40 m+
target_speed:    0 m/s  -> 1.2 m/s
unknown_ratio:   0      -> 30%
```

### 5.3 训练时的底层控制使用方式

训练上层导航时，不需要重新训练关节级控制器。建议冻结现有 Parkour MoE 底层策略：

```text
Navigation Policy 训练中：
    action_high = local_goal 或 cmd
    action_low = Parkour MoE(action_high, obs, depth)
```

这样上层网络学到的是“给底层策略下什么指令能成功到达目标”，而不是重新学习四足步态。

如果某些地形在当前底层策略中成功率不足，应先记录为高风险区域，而不是强迫上层策略规划穿越。

## 6. 监督信号与奖励设计

### 6.1 可通行性标签来源

可通行性标签不应只由几何规则决定，因为“几何上可通行”不等于“当前策略一定能通过”。

建议组合三类标签：

1. 几何规则标签：
   - 根据高度、宽度、坡度、沟渠宽度、桥宽等生成初始可通行标签。
2. 仿真试走标签：
   - 用冻结的 Parkour MoE 从不同角度、速度、起点试走每类障碍。
   - 统计成功率、平均耗时、跌倒率、卡住率。
3. 专家规划标签：
   - 用已知地图和试走成功率生成 teacher costmap。
   - 使用 A* / Dijkstra / RRT* 生成参考路径。

最终标签示例：

```text
pass_prob = success_count / trial_count
cost = time_cost + fall_risk + deviation_cost + energy_cost
mode = argmax(success_mode)
```

### 6.2 导航策略奖励

上层策略奖励建议包括：

```text
R = 目标接近奖励
  + 目标可见/可追踪奖励
  + 路径效率奖励
  + 成功到达奖励
  + 合理跨越障碍奖励
  - 跌倒惩罚
  - 卡住/无进展惩罚
  - 高风险失败惩罚
  - 频繁急转/指令抖动惩罚
  - 不必要绕行惩罚
  - 进入不可通行区域惩罚
```

重要的是区分“合理跨越”和“鲁莽撞障碍”：

- 如果障碍在当前能力边界内，且跨越能显著缩短追踪路径，应奖励。
- 如果障碍超过能力边界，仍尝试通过导致跌倒，应强惩罚。
- 如果平坦绕行代价很小，不必强迫跨越高风险障碍。

### 6.3 目标跟踪奖励

目标跟踪不只是到达目标点，还需要持续保持追踪能力：

```text
- 距离目标越近奖励越高，但保留安全距离
- 目标在视野中心附近奖励
- 目标短时遮挡后重新捕获奖励
- 丢失目标时间越长惩罚越大
- 预测目标位置并提前绕行奖励
```

## 7. 网络结构建议

### 7.1 可通行性网络结构

推荐结构：

```text
local_map [C, H, W]
    -> CNN / ResNet Encoder
    -> map_feature

robot_state / target_state / policy_context
    -> MLP Encoder
    -> state_feature

map_feature + state_feature
    -> Feature Fusion
    -> Decoder Heads
        - pass_prob_map
        - cost_map
        - risk_map
        - mode_map
        - uncertainty_map
```

如果后续引入大范围点云，可增加 PointNet/Point Transformer 分支，但第一阶段不建议直接从原始点云开始。

### 7.2 导航策略网络结构

推荐两种输出形式。

形式一：输出局部路点。

```text
NavigationPolicy(local_map, target_state, robot_state)
    -> local_goal = [x, y, yaw]
```

形式二：输出速度指令。

```text
NavigationPolicy(local_map, target_state, robot_state)
    -> cmd = [vx, vy, yaw_rate]
```

优先推荐局部路点，因为它更容易和传统规划器结合，也更容易限制行为边界。

### 7.3 与现有 Parkour MoE 的接口

新增上层策略不直接输出关节动作，而是输出当前底层策略已经支持的 command：

```text
obs[6:9] = autonomous_cmd * command_scale
```

现有部署中的人为遥控逻辑可以扩展为：

```text
cmd_source:
- manual：遥控器直接控制
- autonomous：自主导航输出
- assist：人为给大方向，自主导航做局部避障/跨越
- safety_stop：紧急停止或阻尼模式
```

## 8. 训练流程

### 阶段 1：建立可通行性数据集

1. 使用当前 `mgdp_parkour` 地形生成器生成大量单障碍和组合障碍地图。
2. 冻结当前 Parkour MoE 底层策略。
3. 在每类障碍上从不同起点、角度、速度进行试走。
4. 记录成功率、通过时间、跌倒率、轨迹偏差、实际消耗。
5. 生成可通行性标签和 teacher costmap。

产物：

```text
- terrain trial dataset
- pass_prob labels
- traversal cost labels
- terrain mode labels
- success/failure boundary table
```

### 阶段 2：训练可通行性网络

训练目标：

- 输入局部高度/点云特征图；
- 输出 pass probability、risk、cost、mode；
- 与仿真试走统计标签和 teacher costmap 对齐。

损失函数：

```text
L = BCE(pass_prob)
  + SmoothL1(cost)
  + CE(mode)
  + SmoothL1(risk)
  + uncertainty calibration loss
```

### 阶段 3：训练路径规划与局部导航策略

初期使用 teacher planner 生成参考路径：

```text
known map + learned costmap
    -> A* / Dijkstra
    -> expert path
```

训练局部导航策略模仿 expert：

```text
local observation -> local_goal / cmd
```

然后再用强化学习微调，使其适应动态目标、遮挡、感知噪声和执行误差。

### 阶段 4：闭环联合评估

把完整系统放入仿真闭环：

```text
目标追踪 + 建图 + 可通行性网络 + 规划器 + Parkour MoE
```

评估：

- 目标追踪成功率；
- 平均到达时间；
- 平均路径长度；
- 跨越障碍次数；
- 不必要绕行次数；
- 跌倒率；
- 卡住率；
- 目标丢失时间；
- 实时推理延迟。

### 阶段 5：实机部署与安全验证

实机部署先从半自主模式开始：

1. 人为遥控为主，自主导航只输出建议路径/可通行性可视化。
2. 开启 assist 模式：上层限制危险方向，人仍控制速度。
3. 开启低速 autonomous 模式：只在简单障碍上自主追踪。
4. 逐步开放楼梯、低矮障碍、窄桥、沟渠等高风险能力。

## 9. 实机部署架构

建议部署进程分层：

```text
Perception Process
  - camera / lidar / depth
  - target tracking
  - SLAM / mapping

Navigation Process
  - map preprocessing
  - traversability inference
  - path planning
  - command generation

Control Process
  - existing Parkour MoE policy
  - motor command sending
  - emergency stop / damping
```

频率建议：

```text
底层控制：        50 Hz，与当前 0.02 s policy dt 对齐
可通行性网络：    5 ~ 20 Hz
局部规划器：      5 ~ 20 Hz
全局规划器：      1 ~ 5 Hz
目标检测/跟踪：   10 ~ 30 Hz
建图：            5 ~ 20 Hz
```

实时性要求：

- 上层导航允许低频，但必须稳定输出短时有效的局部目标。
- 如果上层超时，底层应保持减速、停止或切回手动。
- 任何时候遥控器 emergency stop 优先级最高。

## 10. 安全边界与兜底策略

必须加入安全层，不能完全相信学习网络。

建议硬约束：

- 过高障碍物直接标记不可通行。
- 超过底层策略已验证能力边界的沟渠宽度直接绕行。
- 桥宽低于安全阈值时降速或禁止通行。
- 未知区域不能高速进入。
- 目标追踪置信度过低时进入搜索/等待，而不是盲目冲刺。
- 机器人姿态异常、打滑、卡住、跌倒趋势出现时停止上层指令。

安全状态机：

```text
MANUAL
ASSIST
AUTONOMOUS_TRACKING
SEARCH_TARGET
CAUTION_TRAVERSE
STOP
RECOVERY
```

## 11. 推荐落地里程碑

### M1：离线方案验证

- 生成组合大地图。
- 冻结 Parkour MoE 进行试走采样。
- 得到不同障碍的通过成功率表。
- 训练初版 traversability network。

验收标准：

- 网络能区分可跨越障碍和不可跨越障碍。
- 对楼梯、坡、低矮 hurdle、窄桥、沟渠给出合理风险评分。

### M2：仿真自主导航闭环

- 接入 A* / D* Lite 规划器。
- 使用 learned costmap 规划路线。
- 输出局部路点/速度指令给 Parkour MoE。
- 在随机起点和目标点上完成导航。

验收标准：

- 成功率高于普通 obstacle-only costmap。
- 在合理场景下能主动跨越障碍缩短路径。
- 跌倒率不显著上升。

### M3：动态目标追踪

- 加入移动目标。
- 加入目标遮挡和重识别。
- 加入目标预测位置。

验收标准：

- 目标短时遮挡后可重新捕获。
- 能根据目标运动方向提前重规划。
- 不会因为追踪目标而盲目进入高风险区域。

### M4：实机半自主

- 实机只显示可通行性地图和建议路径。
- 不直接接管速度控制。
- 人为遥控验证网络判断是否可信。

验收标准：

- 地图与实地障碍几何基本一致。
- 网络风险判断与人工判断大体一致。
- 推理延迟满足实时要求。

### M5：实机低速自主追踪

- 开启低速自主导航。
- 限定障碍类型和难度。
- 保留手动接管和急停。

验收标准：

- 平地/缓坡/低台阶/低矮障碍可自主追踪。
- 遇到超能力障碍会绕行或停止。
- 控制指令平滑，不引发底层策略失稳。

## 12. 关键风险

### 12.1 底层能力边界不清晰

如果上层不知道底层到底能跨多宽沟、上多高台阶、过多窄桥，就会错误规划。

解决方式：

- 先做大规模试走数据集。
- 建立能力边界表。
- 可通行性网络必须学习 success probability，而不是只看几何阈值。

### 12.2 仿真地图与真实点云差异

仿真高度图干净，真实点云有噪声、缺失、动态物体和反光问题。

解决方式：

- 训练时加入点云 dropout、深度噪声、地图延迟、位姿漂移。
- 实机先做可视化验证，再接管控制。
- 对 unknown area 保守处理。

### 12.3 上层指令超出底层训练分布

当前底层策略很多 parkour 地形偏前向通关，横移和复杂绕行能力可能不足。

解决方式：

- 上层路径跟踪优先使用转向加前进。
- 对 `lin_vel_y` 限幅。
- 后续可补训底层 omni parkour 能力。

### 12.4 目标追踪与安全冲突

为了追目标，策略可能倾向于走高风险捷径。

解决方式：

- 风险代价必须进入规划器。
- 设置 hard safety constraints。
- 目标追踪奖励不能压过跌倒/不可通行惩罚。

## 14. 最终推荐方案

最终建议采用分三层的工程方案：

```text
第一层：现有 Parkour MoE
负责身体控制和复杂地形运动执行。

第二层：Traversability Network
负责从地图中判断哪里能走、哪里能跨、哪里要绕、哪里风险高。

第三层：Target Tracking Navigation Planner
负责结合目标位置和可通行性地图规划路径，并输出底层可执行指令。
```

这条路线的优势是：

- 最大化复用当前项目已有成果。
- 比纯端到端导航更容易训练和解释。
- 能明确体现“不是所有障碍都避开，有些障碍应主动通过”的核心能力。
- 更适合从仿真逐步迁移到实机。

最终系统应做到：

```text
看到目标 -> 建立地图 -> 判断障碍是否可通行 -> 选择高效路径 -> 输出速度指令 -> Parkour MoE 执行 -> 持续重规划追踪目标
```

也就是让机器狗从“会被遥控着跑酷”升级为“知道什么时候该绕、什么时候该跨，并能自己追上目标”。
